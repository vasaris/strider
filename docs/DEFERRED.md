# DEFERRED — канонический реестр отложенной работы

Единственный источник правды по работе, сознательно отложенной на будущие этапы.
Памяти и разрозненных `HANDOFF_*.md` недостаточно (дрейфуют между сессиями); этот
файл в репо — нет.

## Правило-гейт (см. brodyazhnik-architecture-v1.md, §9 roadmap)

- Критерий выхода этапа N **не выполнен**, пока в этом реестре открыт пункт с
  `DUE ≤ N`.
- Стартер каждой сессии этапа **обязан** эхо-вывести открытые пункты своего этапа.
- Новый отложенный пункт заносится сюда **в той же сессии**, что и решение отложить.
- Закрытие: пункт переносится в раздел «Закрыто» с коммитом, который его закрыл.

`DUE` — самый ранний этап/гейт, обязанный пункт закрыть. Привязанные к этапу
пункты также проставлены инлайн в roadmap-строках архитектурного документа, чтобы
их нельзя было не встретить при старте этапа. *Пункты блока I чата 3.1 (`DZ1`, `O1`, `D1`,
`LG1`, `SA1`, `AUTH1`) и части 2 (`API-RES1`, `DB-ROLES1`, `SEC-RED1`, `NODE1`) проставлены в
§9 архитектурного документа в docs II чата 3.1; `SUPA1` не привязан к этапу — ссылка в §8. Пункты
чата 3.2 (`CT1`, `TRANS1`, `LAT1`, `TERM1`, `SA2`, `API-RES2`, `UI1`, `LOCK1`, `IC1`, `WEARY1`,

### O1 — Порог Ока не проверяется на шаге прибытия и между сценами опасной зоны (движок)
- **Статус:** open (заведён 2026-09-27; находка скелета 3.1, подтверждена ревьюером)
- **DUE:** Этап 4.
- **Что:** карта `sceny_obnaruzheniya`: сцена обнаружения происходит, «когда рейтинг
  Бдительности Ока сравняется с порогом преследования или превысит его». `stepJourney` вызывает

  порог−1 прибытие с Оком на броске пути доводит рейтинг до порога (18 / 16 / 14 по регионам), а
  события `detection` нет.
- **В 3.x недостижимо:** одно путешествие на 7 гексов со стартом Ока 0 до порога 14+ не
  дорастает.
- **Такты (3.3a, верификатор K1 `4224402`):** Око от Испытания похода растёт в такте пути, а порог

  сцены обнаружения, пока игрок не бросит проверку сцены.
