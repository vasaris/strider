## 3. API — `docs/API.md`

Живой справочник: маршруты, формы, порядок проверок, правило выбора прозы, подписи, 19 кодов.
Отступления K4, которые 3.3 должен знать:
- **регенерация** (`POST …/turns/:n/prose`) отвечает исходом **своей** генерации. Заблокированная
  отвечает `prose: null, proseState: 'blocked'`, а GET продолжает показывать прежний принятый
  текст. Клиент перечитывает GET и показывает «оставлен прежний текст» (K5.1);
- **параллельный дубль хода** → 409 **`generation_in_progress`**, а не `turn_conflict`: lock берётся
  до проверок «путь окончен» и индекса. `turn_conflict` — устаревший индекс или дубль из другого
  процесса на вставке.

Телеметрия K5.2: на каждый вызов Хранителя одна строка `keeper_call {...}` в stdout сервера —
model, duration_ms, usage (input / output / cache tokens), stop_reason; при сбое — класс ошибки
(для SDK — фиксированным именем) и HTTP-статус, если есть.

## 5. Что есть в коде (опора для 3.3)

- **Движок.** `stepJourney` за один вызов делает бросок Путешествия, сцену пути и проверку
  обнаружения. На шаге прибытия — только бросок Путешествия, сцены нет; поэтому на смоуке там одна
  панель. Сцена (`engine/src/journey/scene.ts`, `resolveSceneWithRoll`):
  1. Кость испытания с региональным модификатором → тип сцены;
  2. d6 → строка детали (навык или значимая встреча без проверки);
  3. проверка навыка `runSkillCheckWithRoll`;
  4. последствия сцены и Изнурение сцены (если не снято).

  Око растёт на 1 за каждое Око на Кости испытания вне боя — на броске Путешествия, на броске
  таблицы сцен и на проверке, — а также от последствий сцены, дающих баллы Тени
  (`engine/src/journey/effects.ts`).
  В пакет сейчас попадают только проверка сцены (`dice`) и бросок Путешествия
  (`journey.travel_check`); бросок таблицы и d6 детали — нет (`TRANS1`). Все функции чистые, RNG
  передаётся явно.
- **Orchestrator.**
  - `journeyTurn` / `extractJourneyTurn` → `NarrativePackage`;
  - `render.ts` не выдаёт UI-only поля граней;
  - keeper v0.3 (`prompts/keeper.system.v0.3.md`, ранние версии заморожены sha256);
  - `AnthropicLlmClient` с опциональным хуком `onCall` (K5.2).
- **prose-gate.** `scanTurnProse` = стоп-листы + NF1 + SA1, только при наличии пакета.
- **app.**
  - Ход — одна строка `turns` (состояние + пакет, append-only), генерации append-only.
  - Сервис — `app/src/server/service/sessions.ts`, подписи — `labels.ts` + `uiLabels.ts`.
  - UI — `app/src/ui/*`, общие типы — `app/src/shared/api.ts`.
- **Пак.**
  - Карта траты Надежды `kv.mechanics.checks.bonus_dice_hope` (стр. 20; `hope_spend`, `inspired`);
  - благополучный / злополучный — `kv.mechanics.checks.favoured_ill_favoured`;
  - имена в UI — только из пака (структура → `ui_labels.json` с evidence → id). Новые термины
    панели броска — через тот же процесс (`TERM1`).

## 10. Как запускать (Иван)

- БД один раз — `app/supabase/README.md` (роль `brodyazhnik_app`, база `brodyazhnik`), затем
  `npm run db:migrate -w app` с `DATABASE_URL` в шелле.
- Dev: keyed-шелл (`set -a; source evals/.env; set +a`) + `DATABASE_URL` → `npm run dev -w app`,
  страница http://127.0.0.1:3000. Строки `keeper_call {...}` в этом терминале — латентность и
  токены каждого вызова Хранителя.
- Перед `test:all` / `build:app` dev-сервер остановить (`lsof -i :3000` пуст).
- Опционально: `npm run test:pg -w app` с `TEST_DATABASE_URL` на базу `*_test` (вне `test:all`).
